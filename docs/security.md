# 安全与隐私设计

## 威胁模型

假设攻击者能控制以下任一环节：

| 攻击面 | 典型手段 | 本项目的防线 |
|---|---|---|
| 用户输入 | 提示注入诱导 Agent 越权 | 风险等级由 policy 决定，不由模型决定 |
| 网页内容 | 页面里藏指令让 Agent 转账 | 执行器无决策权，写操作必须签名 |
| 被盗令牌 | 重放已批准的指令 | nonce 单次消费 + 签名覆盖参数与时效 |
| 内部越权 | 直接调执行器跳过网关 | 执行器强制验签，无签名直接拒绝 |
| 审计篡改 | 事后修改日志掩盖痕迹 | 哈希链，任何改动都会被 verify 发现 |
| SSRF | 让执行器访问内网 | 协议白名单 + 私网地址拒绝 |

## 凭据处理

- 本仓库**不存储任何明文凭据**。真实部署应把凭据放在独立 Vault，由 Sentinel 侧代填。
- 凭据不得进入模型上下文、不得写入普通日志、不得出现在证据快照中。
- 日志只记录"对象 + 原因码"，不记录账号、地址、订单号原文。

## 数据最小化

- 证据快照默认只保留结构化字段与截断原文，建议留存 7 天。
- 审计记录建议留存 180 天，且只追加。
- 推断出的偏好默认**不生效**，必须用户确认后才参与拦截：模型不能自己给自己放权。

## 权限红线

以下四条不允许为体验或工期让步：

1. 明文凭据不得进入模型上下文或普通日志。
2. 无有效签名的写操作不得进入执行器，不留调试后门。
3. 校验结论为"不确定"时不得按通过处理。
4. 审计写入失败必须阻断执行，不允许先干活后补记录。

## 已知限制（不要在生产直接使用）

- 鉴权是 `X-User-Id` 请求头，**没有真实身份校验**。
- 单租户内存存储，无多租户隔离。
- 未实现按平台维度的凭据撤销与轮换。
- 未实现数据导出/删除的完整生命周期接口。
- 模拟执行器不做真实外部访问，接入真实平台前请重新评估合规与站点条款。

## 报告漏洞

请勿公开提交 Issue。请通过仓库的 Security 页面私下报告，或在 `SECURITY.md` 中给出的渠道联系维护者。我们承诺 72 小时内响应。

# 架构说明

> 目标读者：准备提交 PR 的贡献者、做安全评审的工程师。

## 1. 设计前提

这套架构只围绕一个假设：**模型会出错**。

由此推出三条不可绕过的边界：

| 边界 | 含义 | 违反后果 |
|---|---|---|
| 模型侧零凭据 | 密码、Cookie、支付令牌不进模型上下文 | 提示注入即可拖库 |
| 执行侧零决策 | 执行器只认签名，不判断"该不该做" | 一次幻觉直接改变现实世界 |
| 校验侧零依赖模型 | 是否完成由规则判定 | "我做好了"变成事实 |

## 2. 分层

```
接入层    控制台 / HTTP API       只持有用户会话
编排层    目标解析 · 约束编译 · 调度   可读写任务库，无凭据
规划层    步骤计划 · 候选方案        无凭据、无执行权
Sentinel  权限路由 · 签名 · 审批 · 审计   唯一持有凭据
执行层    隔离执行 · 证据回传        只持有单次令牌
校验层    规则判定 · 三态输出        只读
```

配套两个支撑面：数据（快照、审计、任务库）与观测（指标、告警、回放）。

## 3. 五步主循环

```
Plan → Act(签名) → Observe(证据) → Verify(规则) → Commit(状态)
```

关键点：**Observe 只产出证据，结论必须由 Verify 给出**。这一步决定了"模型说完成"和"事实是完成"不会混为一谈。

## 4. 权限分级

| 等级 | 判定方 | 例子 | 行为 |
|---|---|---|---|
| read | policy 表 | 查价、查账单、读页面 | 自动执行，写入审计 |
| confirm | policy 表 | 提交表单、下单 | 生成审批，人工确认后签名 |
| forbidden | policy 表 | 支付、代发消息、签约 | 代码层拒绝，不提供审批入口 |

风险等级由 `internal/policy` 决定，**不由规划器提供**。规划器把支付标成"只读"也不会生效。

## 5. 幂等与重放

- 目标指纹：`user + kind + object + metric + op + value + channel` 哈希，阻止重复建任务。
- 意图签名：HMAC 覆盖 `id/task/run/action/risk/nonce/expires/params`，任何字段变更都会导致验签失败。
- nonce 单次消费：验证通过的 nonce 进入已用表，重放直接拒绝。
- 审批内容哈希：用户批准后若参数被改写，审批自动作废。

## 6. 熔断

| 层级 | 触发 | 动作 |
|---|---|---|
| 任务级 | 连续 3 次失败 | 停止任务，生成事故记录 |
| 场景级 | 赔付/投诉超阈值 | 关闭该场景写操作（预留） |
| 全局级 | 运维判定 | `POST /api/system/pause` 秒级生效 |

熔断是预先写进系统的安全气囊，不依赖人工判断。

## 7. 成本

`单用户日成本 ≈ 任务数 × 日轮询次数 × (抓取 + 模型) + 容器摊销 × 重试放大系数`

只读监控单任务日成本约 0.1 元量级；执行类因多次验证与重试，成本高 3–5 倍。因此**没有交易返佣或订阅收入的场景，不应开放自动执行**。

## 8. 扩展点（贡献者最常改的地方）

| 想做的事 | 改哪个包 | 接口 |
|---|---|---|
| 接入真实平台 | `internal/executor` | `Executor.Execute` |
| 换成 LLM 规划 | `internal/planner` | `Planner.Plan` |
| 增加校验规则 | `internal/verifier` | `Engine.Verify` 内新增规则族 |
| 调整权限映射 | `internal/policy` | `RiskOf` |
| 换存储 | `internal/store` | 现有方法集 |
